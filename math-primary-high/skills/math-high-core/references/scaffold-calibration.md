# Math Scaffold Calibration

Read before giving a hint, example, or support, including a planned opening example. Primary method selection belongs to `references/math-teaching-core.md`; this file calibrates help within it.

## Match Support to the Step

Apply **Guide before revealing** and its **Informed full-solution choice** exception in `learn-core`'s `references/pedagogy-core.md` before every example or explanation. Explicit complete-solution requests use that shared path rather than this guided scaffold sequence. In guided work, first allow one reachable attempt; respond to what the student has actually shown by clarifying a condition, asking about their strategy, connecting a representation to notation, or suggesting a simpler case. Planned explicit instruction and an explicit request to see a method do not establish an impasse. When the shared gate justifies a demonstration, verify and label the smallest necessary example or blocked step, then leave a reachable inference to the student. Fade support across subsequent turns; avoid fixed failure quotas.

A confirmed missing prerequisite tool first enters a recorded child task per `references/prerequisite-learning.md`; an inline worked example in the parent does not replace that entry. Inside the child, once its own tools are available, the normal example/explanation/fading options below remain available. Unknown readiness first calls for a purposeful probe, not automatic remediation.

Choose one action and one pending question, then wait. Keep the student's viable approach and withdraw support once they can continue. A request for explanation calls for support matched to the obstacle under the shared gate, not an automatic whole-task demonstration; do not enforce a mechanical hint ladder. Feynman mode preserves the student-presenter role under shared rules.

## Support Options (grades 4–6)

Choose the smallest useful option, not a required sequence:

1. Rephrase the same quantities and conditions without adding a solution.
2. Focus attention on one equality, unit, boundary, or comparison.
3. Connect a representation: words, a bar diagram, table, number line, symbols, or objects. The math board is optional; use it only if available and chosen. Tool use does not require switching to the lower-primary package.
4. Give an analogous example with different numbers and a partially completed step.
5. Give a verified worked example with a reason for the key step, followed on later turns by faded support and a fresh independent check.

If a student has tried and has no way forward, one interest detail may restate the same relationship per `references/math-personalization.md`; return to the target when they can continue. Repeated sticking goes to diagnosis and sustained non-response to shared rules.

## Evidence

Record examples, hints, and simpler cases as supported work. Agreement with an example is not independent understanding; only fresh independent application verifies it. Adjust one dimension at a time per `references/adaptive-thresholds.md`, without presuming a belief or confidence problem from an error.

With a submitted edit history, use only observable changes in the current message to ask one question about the meaning of the representation. Counts and undos alone do not establish difficulty, and missing history does not justify asking for an unsent draft. The formative-assessment row of `references/math-teaching-core.md` supplies feedback and self-check moves, not another mandatory sequence.
