# 技能、教学环节与规则所有权

[English](skills.md) | [中文](skills.zh.md)

六个内部技能：一条主线、一个规则所有者、四个子技能。它们都不可由用户调用，也不占用 `/` 入口；`/learn` 与 `/learn-feynman` 经共享生命周期到达本带。本页给出技能清单、调度约定、两个数学带如何共存，以及本带本地保留什么。

## 技能清单

| 技能 | 职责 |
|---|---|
| `math-high-session` | 教学主线、恢复焦点、四个教学环节的唯一调度者、本轮唯一回合段的合并者 |
| `math-high-core` | 共享规则——教学、诊断、支架、活动分配、画板、学科契约——参考文件按条件读取 |
| `math-high-diagnose` | 策略诊断、先修检查、错题分流、有证据的阶段估计 |
| `math-high-practice` | 诊断／对比／变式／连接，另有非分层巩固与回访；子题逐个推进 |
| `math-high-student-problem` | 学生编题、AI 诚实作答、学生批改；找错另行明确标注 |
| `math-high-application-modeling` | 真实情境建模：情境、方案、表示、数量与单位、验证、结论 |

## 调度

- 只有 `math-high-session` 调度四个子技能。子技能只回传证据与下一动作信号，彼此不互相调用。
- 等待学生时保留原步骤。证据足够且无待答问题时，同轮最多两次子技能调度。
- 仅教学主线合并唯一回合段。后续检查走既有的下一步交接，不承诺定时。
- 这是指令层的集中调度约定，不是运行时调用隔离。

## 两个带、一个科目

- 两个包都用唯一技能名——这里是 `math-high-*`，那边是 `math-low-*`——所以在同一个 `math` 科目 id 下可以并存安装。共享教学解析——`learn-data` 的 `references/teaching-resolver.md`——为新任务选带（1–3 年级 → 低年级包，4–6 年级 → 高年级包，无年级 → 低年级包），并在任务未完成时保留已解析的带；`supported_stages` 只声明默认表达与流程。
- 优先级不是内容门槛：低年级带支持更高内容，进行中的任务也不会因为装了另一个包而被热替换。
- 本带的写法以高年级认知与表达为默认，但不是低年级包的复制；差异只在各自 `references/` 里。
- CGI 保留关注学生真实策略的作用，不再统领每一课。概念用 CPA，程序可用显式教学，陌生题用 Pólya，辨析与迁移用变式，规律用探究论证，真实决策用建模；形成性评价贯穿。步骤见[教学核心](../skills/math-high-core/references/math-teaching-core.md)。
- 用画板、需要图示或补基础，都不意味着切到低年级带。先判断先修缺口、支架与适配；换带是学生阶段问题，不因一次答错或一次工具需要而决定。

## 本带拥有什么、借用什么

- 学生编题、练习证据、画板协议与手写读取只在 [`baicai-edu-math`](../../math-common/README.md) 写一份；本带只在出现对应分支时按名加载。
- 手写契约由本带核心技能的条件行直接加载，与年级无关且没有本地增补：先读契约，再加载 `learn-read-image`。
- 本地保留：按任务选方法、直接计算与显式教学开场、批次归因、不自动清板、建模子技能。题型按教学目的选择——故事、计算、图表、等式和论证各有用途，同一关系换新场景可以检验情境迁移。
- 共享契约包不参与教学选型，也永不替代本带的 `core` 或 `session`。流程选择、确认、保存与新任务解析由 `learn` 承接；低年级带按已确认的学生阶段适配，不按一次答错或一次工具需要。
- 两个独立所有者：[活动分配](../skills/math-high-core/references/learn-act-allocation.md)决定做什么，[教学核心](../skills/math-high-core/references/math-teaching-core.md)决定怎么教。方法名与已安装落点见[方法](methods.zh.md)。
