# Logical Constraints and Solution Completeness

Read for interacting finite assignments, justified elimination/propagation, or solution count. `math-high-session` keeps the current act. Use Ordered enumeration in `references/mathematical-strategies.md` for coverage and `references/proof-teaching.md` for scope and warrants.

Define roles, values, repetition and quantifiers (e.g. exactly one color per person versus using each color exactly once). Swapping roles usually changes an assignment. Clarify one decisive ambiguity instead of adding an all-different rule. Use `operation-meaning`, `data-graphs`, `multiplicative-thinking` from `references/topic-map.md` as needed; verbal propagation is valid.

Mark allowed so far, not yet checked, excluded with reason, and forced with reason. A blank excludes nothing; local permission does not guarantee a complete solution. Exclude only by an original condition or justified consequence, preserving every possible solution.

| Student evidence | Next move |
|---|---|
| Too many conditions | Organize options for one role or use an already fixed value; leave the next exclusion open |
| Misreads/exhausts a once-only value | Clarify once-only or follow its consequence: if C uses red, can B still use it? Try two roles/two colors if needed to probe tool use |
| Crosses out a blank or asserts impossibility | Ask which condition excludes it; reopen until justified |
| Valid assignment presented as unique | Keep it; ask which alternatives it excludes and why |

At a real decision, ask what the student's exclusions establish and what remains. Probe only decision-changing unknowns, not calculation by default. For a confirmed gap follow `references/prerequisite-learning.md`; carry original answer, exclusions/reasons, help and pending position. Tool readiness alone is not independent parent selection.

## Strength of conclusion

- **Existence:** one complete assignment checked against all original conditions.
- **Uniqueness:** existence plus justified exclusion of every alternative by propagation or exhaustive branches.
- **Multiple:** two witnesses refute uniqueness; an exact count needs full coverage.
- **None:** direct contradiction or exhaustive justified exclusion, not failed attempts.
- **Underdetermined:** state what remains possible; clarify unspecified rules without inventing clues.

## Private verification

Keep answers private in independent openings. Guided work follows **Guide before revealing**. Only explicit full-solution requests use `learn-core`'s informed full-solution choice (parent or child); a hint request does not trigger that choice.

Check all original conditions for any forced result. If a clue is removed, keep old witnesses, reopen exclusions relying on it and recount. An added contradiction needs identification of incompatible conditions, not an exhaustive list or silent repair. Relabeling tests structure, not a boundary; an agreed decisive change requires rechecking feasibility and completeness.

## Attribution and completion
