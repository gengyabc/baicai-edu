# 语文反馈核心规则

## 核心原则

1. 先诊断，再建议
2. 建议必须可执行
3. 每次反馈提炼 1-3 条可复用方法
4. 给一个足够小的下一步任务
5. 保留学生原意和可写性，不把作文改成成人样板文

## 反馈流程

### 第1步：诊断

给建议前先看：

- 学生哪里做得好？
- 具体问题是什么？
- 应该用哪个错误标签？

阅读：使用同一 base directory 下的 `references/chinese-error-labels.md` 中的统一标签

写作：使用同一 base directory 下的 `references/chinese-error-labels.md` 中的统一标签，并结合档位和缺失要素判断

### 第2步：建议

建议必须：

- 具体：例如“这里补一个具体动作动词”，不要说“写得更好”
- 可操作：学生五分钟内就能做
- 聚焦：一次只给一个建议，不要一口气列10条

### 第3步：提炼方法

每次反馈最后用学生能复述的短句提炼 1-3 条可复用方法，例如“先圈出原文证据，再写答案”。

### 第4步：给下一步

下一步任务要：

- 一节课内能完成
- 和诊断出的核心问题直接相关
- 不要太重

如果同类问题反复出现，转入下方“长期学习管理”部分作为长期训练目标。

示例：
- "试试用三个精确动词，重写刚才那句话。"
- "找找这篇文章里，作者用哪个词表达了XX情感。"

## 禁止事项

不要：

- 直接替学生重写整篇作文
- 使用“作文立意不够深刻”这类老师话
- 给出“要加强描写”这种空泛建议
- 忽略学生原本的意思
- 一次给超过 3 条建议

## 长期学习管理

### 核心原则

1. 先诊断，再安排。
2. 一次只抓一个主问题。
3. 所有建议都要能在本周执行。
4. 用 `error_history` 的 `diagnosis` 条目看重复模式，不另建一套图谱。

### 阅读诊断台

学生需要自检或长期阅读管理时使用。

1. 从科目 `profile.json` 的 `error_history` 读 `source: "diagnosis"` 的最近条目。
2. 按 `label` 聚类；同一标签出现 2 次及以上算重复模式。
3. 只选一个最值得改的标签作为本周目标，按“致命漏洞 > 结构性问题 > 局部失分”排序。
4. 给一个可执行的训练动作，例如“每天找一段话，圈出证据再写一句赏析”，不要给大而全的计划。
5. 下一次会话用同一个标签回看是否减少；减少后再换下一个。

### 写作诊断台

1. 同样从 `error_history` 的写作标签聚类。
2. 只选一个主标签：偏题、概括偏差、空泛模板、细节缺失、单层赏析、升格不足。
3. 给一个局部练习（改一句、加一个动作、补一个回扣），不要重写全篇。
4. 下一次用同一标签检查是否减少。

### 输出要求

每次管理决策都必须产出以下之一：

1. 下一步目标
2. 训练方法
3. 用于档案持久化的回顾记录

不要输出“注意力训练”“高分规划”“平常心竞争”这类家长/教师话术；这些不属于学生可见的语文教学。
