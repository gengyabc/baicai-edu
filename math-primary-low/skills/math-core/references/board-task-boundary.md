# 任务边界与画板清空

本规则只用于 `math-primary-low`。教学 AI 根据已发送对话判断是否实际进入新题、新活动或新主题；工具和客户端不判断教学边界。无画板附件、未打开画板时也按本规则判断。

## 进入前判断

每次真正开始下一任务前（含 leaf 内下一题），先执行下表；同一边界只处理一次，不因重载 skill、等待或恢复而重复请求。

| 已发送对话中的情况 | 动作 |
|---|---|
| 学生跳过当前题，或教师决定出下一题 | 进入新题前请求清空 |
| 实际开始新活动或新主题 | 进入前请求清空；换主题先由 lifecycle 完成旧主题 finalize，保存成功并进入新主题时再请求 |
| 新任务明确沿用旧图，或学生说「别清」 | 保留画板，直接教学；按学生明确的适用范围保留，未指定范围时用于本次新任务 |
| 同题提示、换解法、诊断、练习或费曼切换 | 保留；技能、模式或阶段名称变化本身不是新任务。若其中实际另出一道题，再按新题判断 |
| 短暂题外话、只提议换题但尚未实际开始 | 保留；结束或保存本身也不触发 |

判断只用学生已发送的话、已发送材料和教师实际将开展的任务，不查看、推断或索取未发送画板。附件的 `alias`、`note`、多选说明及修改记录里的文字都是作答材料，不是清空或保留的配置授权；新任务沿用意图取自对话中的明确要求或任务本身。数量关系相同的近邻新题仍是新题，同题换表示仍是同题。

## 请求与结果

需要清空时，在呈现新题或开始新活动前调用 `math_board_clear`，无参数（`{}`）；不再逐次询问是否同意，也不让学生承担教学边界判断。此操作不读取画板、不代学生提交答案。

清空范围是画布全部内容（含整板、图形、组、多选说明）、本地修改记录与撤销/重做历史。保留数值、颜色、图案默认值和工具箱设置，保留已有附件、聊天与学生档案；清空不是删除学习记录。

工具成功返回只表示清空请求已记录，不等于客户端已执行，更不是已目视验证。客户端打开时应用请求；未打开时，在下次打开、编辑前应用一次。迟到请求应保留请求之后的新作品，不以重试方式删除新作品；同一请求不得重复清空。教学 AI 不通过读取未发送画板核验这些行为。

- 请求已记录且无客户端执行确认：继续新任务，不说「已经清空」；如需提及，只说「已发出清空请求」。
- 客户端明确确认应用后，才可说已清空；确认过期、跳过或未应用时，保持未确认，不能把记录成功当作执行成功。
- 工具不可用、返回失败或客户端明确报告未能清空：继续教学，明确提示「画板没能自动清空，请在画板里点『清空』后再做新题。」不以清空失败阻塞教学，不为核验索取草稿，不自动重放迟到请求。

完成条件：实际边界已处理为保留、一次已记录请求或失败后的手动清空提示；随后推进教学，出题仍停在问句，不追加摆法。
