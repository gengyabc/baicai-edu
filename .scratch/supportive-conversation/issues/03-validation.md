# 03 回归验证与文档收尾

Status: resolved
Blocked by: 01, 02

## 范围

验证[更新方案](../spec.md)全部行为场景。先读取现有测试和文档约定，再做定向修改。

## 工作

- 在现有技能契约测试中覆盖新参考可达性、所有权、选择卡边界、纯支持与拒绝规则，避免只断言某个中文按钮字符串。
- 按方案逐条进行人工多轮回放，记录提示输入、实际输出、通过或失败及限制；特别检查拒绝后多轮闲聊是否再次劝学。
- 增加定位说明回放：担心刷题、已能独立运用、学习疲劳、只聊天或结束；检查是否少量验证而非凑题量，是否承认精力成本，是否以“提升能力”继续施压，是否把聊天包装成训练。定位说明应按需出现，不变成每轮宣讲；合理巩固与长期保持的验证仍需保留。
- 更新受影响的调用图或使用说明；仅有指针变化时不制造额外架构组件。
- 检查设计稿具体研究数字的出处；无法补齐时标记待核实，不将其写成运行时效果保证。
- 运行 node scripts/check-skills.mjs 和 node --test scripts/skill-contracts.test.mjs，核查每条命令退出码，失败先调查。

## 验收

静态检查与回归通过；人工场景逐项有记录，未执行项目明确标注；不以静态断言宣称儿童心理或学习效果有效；无修改学生数据、发布或安装操作。最终交付列出改动、验证结果和未决风险。
