# The first-run tutorial and safe practice

[English](tutorials.md) | [中文](tutorials.zh.md)

During practice none of the three pages shows the teacher message strip (`.eb-question`): it is the context of real answering, and the tutorial uses its own step rail to say what to do now; exiting practice restores it unchanged. Every control in the practice interface is a bordered button, and borderless text-style buttons are no longer used.

## The quantity page tutorial

The quantity page enters its own isolated safe practice explicitly through "More actions → View tutorial"（更多操作 → 查看教程）: adding repeatedly, dragging and releasing, adding again, single select / multi-select / deselect, and finally simulating "Put into answer". A step advances only when the real operation in that step succeeded and the goal state is met; a drag preview, a failed add and a wrong selection do not pass. Both languages point at the touch "append selection" path; the practice shapes are marked 1 and 2. No put-into-answer entry point in practice touches the input box or uploads an attachment; the student can "Exit practice"（退出练习） at any time, and must exit after finishing before real answering continues. Completing the basic practice means only that the operations were done; it does not mean mathematical mastery or that other chapters are complete.

The real quantity page stays mounted, and practice uses a different state owner: objects, notes, edit history, undo history, selection, viewport, settings and options are not written back; host settings / clears still apply to the real page, and exiting does not restore an old backup over those updates. The practice interface is a narrow step rail to the right of the canvas: this chapter's title and position, this chapter's step list, this step's goal, the storage hint, and reset this step, skip this step, make up skipped steps, practice this chapter again, all chapters…, exit practice. Other chapters are folded into the "All chapters…"（全部章节…） directory, which distinguishes not started, in progress, completed and skipped, and no longer permanently occupies space above the canvas. After exiting, switching pages or refreshing, the real draft is still the default; only entering the tutorial explicitly again restores the current chapter, step and matching practice frame (including notes, undo / redo, edit history, creation colour, the pattern rail, selection, zoom / scroll and the attach-history option). Reset restores this step's starting point; when skipping an operation that later steps depend on, it only gives later steps a practice starting point and does not count as done by hand. Practicing one chapter again does not clear other chapters. When browser storage refuses, is corrupt or is an incompatible version, the resume rail shows a storage hint and the student can continue / exit or practice this chapter again; it does not pretend the save succeeded. Opening the quantity page for the first time no longer enters this chapter automatically: a lightweight operation tour plays once first (the same spotlight hints as the old version, where an item counts only when the student actually performs it, and the student can "Skip tutorial"（跳过教程）), and the tour's last step says that "More actions → View tutorial" holds the full tutorial; after the tour ends (finished or skipped) the bottom left of the canvas keeps one row, "Want to learn more operations?"（想学更多操作？） plus a "View tutorial"（查看教程） button, which disappears after it is followed or dismissed. Step 5 of the tutorial saves a note: that note card must not be dismissed away in this step, or the page asks the student to save first, so that the tour never stops at a place with nothing to click. The full tutorial starts only when the student enters explicitly, and it resumes the saved chapter and frame; a board that already has practice records no longer plays this tour automatically. To see it again, "More actions → View operation tour"（更多操作 → 查看操作导览） replays it at any time; it replays only the spotlight hints, does not write practice progress and does not affect per-chapter resuming.

## The geometry page and teacher demo page tutorials

The geometry page enters the same isolated safe practice through "More actions → View tutorial"; the basic chapter practices, in order, the point tool and placing a point, a segment, a triangle, closing a polygon, a circle, selecting a specified point, and deselecting, and finally simulates "Put into answer". Each step recognises only committed successful operations: selecting a tool alone is not placing a point, a segment's first click does not complete it, and an unclosed polygon outline and a circle with only its centre do not pass; each later step reuses the points and shapes of the previous step and does not rebuild the frame. Geometry practice uses only one read-only geometry snapshot and the student's board note, and has no geometry edit history; this step and every other step upload nothing, attach no file, do not change the input box and send nothing. Practice uses a separate state owner and the `practice:v2:geometry` record; the real geometry draft, undo history, selection, viewport, grid / snap and file memory are not written back; legal host changes are not overwritten by an old backup, and closing the board mid-practice destroys only the practice. The step rail, chapter directory, reset this step, skip, make-up, resuming and single-chapter retry match the quantity page, both languages can complete it, and closing a polygon and deselecting can also be completed with touch only. Opening the geometry page for the first time likewise plays a lightweight operation tour once; the full tutorial is entered explicitly from "View tutorial", and once practice records exist the tour no longer plays. The teacher demo still guides only when a figure already exists, and does not start `teacher-demo-basics` without one; this short guide also uses the same step rail and hides the teacher message strip while it runs, restoring it after exit. The demo page keeps its own permanent tutorial entry: one "View tutorial" at the bottom right, at the other end of the same bottom edge as "Back to conversation"（返回对话） at the bottom left; after the step rail is collapsed it can be opened again from here, a completed short guide replays from step one, and a skipped one resumes at its recorded end position from the original record (the rail still marks it skipped, and this chapter can be practiced again). With no figure the guide does not start and only says there is no figure to practice on yet; while the guide is open this entry is hidden, because the step rail already has the steps and "Exit practice".

## The safe tutorial extension interface

The first time a given board is opened the lightweight tour plays once only: it writes no `practice:v2`, writes no key of the other side, and starts no chapter automatically; the full tutorial is entered from "View tutorial" and resumes the saved chapter and frame. The v1 seen flag is not completion, is not migrated into practice progress and is not deleted; when a `practice:v2` record already exists the board counts as already introduced and the tour no longer plays.

- [practice.js](<../src/quantity/practice.js>)'s `createQuantityPractice(saved?)` keeps the `snapshot()` / `observe(event)` goal interface; the saved value contains `index` and `targets`, and restoring itself does not check the goal. Only the before and after states of committed user operations (`add`, `move` with `submitted`), explicit user selections (`select`) or a simulated `insert` are fed in; failed operations do not pass. Restores, presets, host updates, programmatic automatic selection and drag previews must not be fed to goal judging, and no mathematical answer is judged.
- [practice-progress.js](<../src/shell/practice-progress.js>) is the lifecycle module shared by geometry, the teacher demo and later quantity chapters: `createPracticeProgress({mode, chapters, storage?, validateFrame?})`, returning `snapshot / enter / observe / saveFrame / reset / skip / retryStep`. `enter()` restores the saved current chapter; `enter(id)` enters the given chapter; `enter(id, {retry:true})` retries only that chapter. `observe(event, frame)` must be passed the full frame after a committed operation; `saveFrame(frame)` saves only the frame and never passes the goal. `reset()` restores both this step's starting frame and its goal state; `retryStep(index)` applies only to an already skipped step and makes it up from that step's own starting point; before the make-up the original goal / frame pair is saved as a pair, and after the make-up succeeds or the step is skipped again the caller returns to the original pending step or end position without resetting later completed / skipped states and step starting points. That return position also survives a refresh, and only an explicit whole-chapter retry resets the whole chapter. The return value contains `current / goal / frame / chapters / persistence / supplementing`; the caller applies the returned frame but must not send the applied action into `observe` again; when `observe` flips `supplementing` from true to false, the caller must apply the returned continue-practice frame rather than only swapping the hint and leaving the temporary make-up objects behind.
- A chapter is defined as `{id, titleKey, steps:[stable step ids], optional?, start(previousFrame), createGoal(saved?), skip(savedGoal, frame)?}`. A goal returns `snapshot()` / `observe(event)`; its snapshot must contain an increasing `index` and `completed`, and one event advances at most one step. The quantity page additionally needs `step / total / targets` for hints and numbering. `start(null)` must provide an independent and sufficient practice starting point; entering an unstarted chapter in sequence receives the previous chapter's frame and may keep its results. `skip` returns `{goal, frame}`, in which the goal has moved to the next step and the frame has what the next step depends on; chapters with no dependency may omit it. A starting point supplied by the program must not complete an operation automatically.
- The stable quantity basics chapter id is `quantity-basics`, with steps `add / move / add-second / select-one / select-many / deselect / insert`. Later tickets should each add an independent module; suggested quantity chapter ids are `quantity-organize / quantity-notes / quantity-adjust / quantity-insert / quantity-files` (`quantity-adjust` is already delivered, see below), geometry uses `geometry-*`, and the demo uses `teacher-demo-basics`; do not change the basic chapter's step sequence or reuse the old v1 tutorial. The quantity extension factory receives `{M,T,emptyFrame}` and returns the chapter definitions above. Wiring only requires importing and inlining that factory in [build.mjs](<../build.mjs>), appending it to `Browser.quantityPracticeChapters: [factory, …]` (empty by default), and adding bilingual goal copy; do not change the shared lifecycle or the real draft owner. The quantity adjust and restore chapter `quantity-adjust` ([src/quantity/practice-adjust.js](<../src/quantity/practice-adjust.js>)) covers Q14–Q19: its steps are `adjust-color / adjust-color-add / adjust-pattern-add / adjust-pattern-use / adjust-pattern-hide / adjust-change / adjust-undo / adjust-redo / adjust-zoom / adjust-fit / adjust-clear / adjust-fresh / adjust-trace-option`. Each step accepts only a real change committed by the student: clicking the current creation colour repeatedly, only opening the pattern library, clicking an already fitted view or an unavailable undo / redo do not advance; undo / redo must match the board before and after that explicit change; confirming a clear requires existing content in the practice and wipes shapes, all notes, the edit history and the undo history together, after which `adjust-fresh` requires adding an object again in the fresh stage before the non-empty snapshot ahead of put-into-answer counts as complete. The page adds only these commit events (colour level, pattern rail add / remove, undo / redo, real zoom / fit, confirmed clear, attach-history option) and does not change the shared lifecycle, real draft writes or the host clear tool; after exit / refresh, resuming restores the same step and the paired before and after boards. The build inlines this factory in the client and [tests/practice-adjust-bundle.test.js](<../tests/practice-adjust-bundle.test.js>) verifies it. The geometry / demo pages reuse it directly through `shared.createPracticeProgress` and `shared.createPracticeRail(React,t)`, using their own `mode` and matching frame validators; they do not pass for each other's completion records.
- The quantity organize chapter `quantity-organize` ([src/quantity/practice-organize.js](<../src/quantity/practice-organize.js>)) covers Q04–Q09. Its steps are `organize-name / organize-reselect / organize-peer / organize-group / organize-group-name / organize-ungroup / organize-merge / organize-split / organize-copy / organize-crossout / organize-delete`. Judging recognises only operations the student has already committed and the board before and after the commit: a valid new name, reselecting and reading that name back, a second object renamed to the same name, a new group containing two marked members, changing the group's current name, disbanding that group, merging under the existing rules, splitting by source, copying with the original object still present, crossing out with the object still present, and deleting that object with the remaining objects still present. An empty name, naming some other object, adding extra objects, a one-member group, a failed or disabled merge, splitting some other object, copying some other object, treating a cross-out as a delete, deleting some other object or clearing the whole board all do not advance. Grouping is not merging, a greyed merge result is not an error, splitting depends on the source, and this chapter judges no operation or mathematical answer. The names, groups and merged objects that `skip` prepares are not fed into `observe`. The page reports only these successfully committed operations during practice. The factory is chained after `createQuantityAdjustChapter` and verified by [tests/practice-organize-bundle.test.js](<../tests/practice-organize-bundle.test.js>).
- The quantity notes chapter `quantity-notes` ([src/quantity/practice-notes.js](<../src/quantity/practice-notes.js>)) covers Q10–Q13. Its steps are `notes-deselect / notes-board / notes-board-read / notes-object / notes-object-check / notes-group / notes-group-read / notes-selection / notes-selection-check`. Only a non-empty note that has been committed and is written on the target of the current selection passes: deselect first and then save a board note, and reopening reads it back; after a specified shape, the target group and the specified multi-select set each save their own note, checking on a different target shows the text did not bleed across. Empty text, cancelling, a save that does not change the board, and writing on another shape, member, another set of objects or the whole board all do not advance. A newly added shape is selected automatically; if the target of the board-note step is a shape, group or multi-select, the page writes nothing and this step does not pass. A note is the student's own words, not a checked mathematical conclusion. `skip` only prepares the selection, group or already written preceding text that the next step needs, and does not feed the note the student must write in this step into `observe`. The page reports committed notes and note-card opens only inside practice. The factory is chained after `createQuantityOrganizeChapter` and verified by [tests/practice-notes-bundle.test.js](<../tests/practice-notes-bundle.test.js>).
- [view-component.js](<../src/quantity/view-component.js>)'s standalone `PracticeBoard` reuses the quantity editor, but `practice` is fixed for the component's whole lifetime; the real `Board` does not unmount, does not swap storage keys and does no backup restore. The quantity practice full frame is `{board,trace,history:{past,future},selection,zoom,fit,attachTrace,toolValue,append,scroll:{left,top}}`, all restored after domain validation. Practice forbids normal draft persistence / projection sync / file memory and input box access; only the `quantity-files` chapter may save and open practice files, and it still remembers no real file handle. Closing destroys only the practice owner. The separate browser key is `baicai-edu-math-board:practice:v2:<mode>`, kept apart from the session draft and the old v1 seen flag; the current chapter, goal, step states, the full frame and each step's starting goal / frame are saved atomically. Corrupt data is not overwritten automatically, and only an explicit retry saves again; when writing is refused practice still works in memory. File handles, host projections, the real draft or the student profile must not be put into the frame.
- `createPracticeRail(React,t)` renders the generic step rail to the right of the canvas: this chapter's title and `N/M`, this chapter's step list (completed / skipped / current), this step's goal, the storage hint, and reset this step / skip this step / make up skipped steps / practice this chapter again / all chapters… / exit practice. It receives `{progress,chapters,onNavigate(command,value),onExit,goalKey,stepKey,notice?,extra?,goalText?}`; `goalKey` / `stepKey` are given by the caller from its own copy prefix, and `goalText` is used by the teacher demo page to replace an unavailable hint. Other chapters are listed only in the "All chapters…" dialog, the optional flag is shown separately, it does not block the basic chapter, and completing the basic chapter does not claim the whole set is complete. The caller keeps an exit entry that is always available and applies the returned frame to the separate practice owner.
- [geometry-basics.js](<../src/geometry/geometry-basics.js>) is the standalone module for the geometry basic chapter and does not change the shared lifecycle. `createGeometryPractice(saved?)` keeps `snapshot()` / `observe(event)`, and the snapshot contains `index / step / total / targets / completed`; it accepts only drawing increments the page has committed (`draw` with `before` and `after`, and a closed polygon additionally with `closed:true`), explicit user selections (`select`) or a simulated `insert`. Tool selection, a half-placed point, a failed draw, a restore or a program preset do not pass; this project measures no length or angle and judges no parallel, perpendicular, equal, collinear or numerical conclusion. `createGeometryPracticeFrames(G)` provides `empty()` and whole-frame validation for geometry practice frames (board, undo history, selection, tool, pending points, construction input, auxiliary lines / grid / snap, zoom, scroll), and any corruption rejects the whole frame. `skip` on `createGeometryBasicsChapter({G,emptyFrame,createGoal})` only supplies what the next step depends on (a placed point, segment endpoints or a closed shape), and the supplied objects do not count as done by hand. The geometry extension factory receives `{G,emptyFrame}`, is inlined in [build.mjs](<../build.mjs>) and appended to `Browser.geometryPracticeChapters: [factory, …]`, with chapter ids using `geometry-*`; do not change the basic chapter's step sequence.
- The geometry construction chapter `geometry-construct` ([src/geometry/geometry-construct.js](<../src/geometry/geometry-construct.js>)) covers G06–G09. Its steps are `construct-parallelogram / construct-rectangle / construct-select-side / construct-midpoint / construct-drag / construct-auxiliary / construct-auxiliary-off`. The parallelogram and the rectangle accept only a committed new shape from the matching tool, and an ordinary polygon or an unfinished preview cannot stand in; taking a midpoint accepts only the derived midpoint generated from the two ends of the selected side; dragging accepts only that a marked free point has changed position after release, and a derived point cannot be dragged directly and is not the target of this step; an auxiliary line requires first turning it on and committing a new shape whose `role` is `auxiliary`, then turning it off, and flipping the switch alone does not count as drawn. Success does not look at where on the canvas the shape landed, and does not measure length or angle, or judge parallel, perpendicular, equal or collinear. The factory is verified by [tests/practice-construct-bundle.test.js](<../tests/practice-construct-bundle.test.js>).
- The geometry edit and notes chapter `geometry-edit` ([src/geometry/geometry-edit.js](<../src/geometry/geometry-edit.js>)) covers G11–G16. Its steps are `edit-rename / edit-text-add / edit-text-change / edit-delete / edit-point-note / edit-element-note / edit-caption / edit-deselect / edit-board-note`. Renaming accepts only the new name of the specified point, with the original shapes still referring to the same point; text must be added first and then that same one changed, and starting another one does not count. Deleting accepts only the specified object, and another object that was already there at the start must remain, so clearing the whole board cannot stand in. Point notes, shape notes and the board note are each written separately, and a text element cannot stand in for a shape note; a shape note must be within 20 characters for the short label to appear, and that label must then be clicked directly to change the original note, while only opening the card does not count. In the board-note step, if the target is a point or a shape the page writes nothing, and a newly appearing selected object must not capture the note either. Notes and text are the student's own words, and no geometry conclusion or answer correctness is judged from them. The factory is chained after `createGeometryConstructChapter` and verified by [tests/practice-edit-bundle.test.js](<../tests/practice-edit-bundle.test.js>).
- The quantity files chapter `quantity-files` ([src/quantity/practice-files.js](<../src/quantity/practice-files.js>)) and the geometry files chapter `geometry-files` ([src/geometry/geometry-files.js](<../src/geometry/geometry-files.js>)) are both optional advanced chapters, and the steps of both are `files-save` then `files-open`. Saving passes only after the practice file has been fully written through a file handle, or after a download has already started; clicking the menu alone does not count. A successful handle uses `practiceFileSaved`. A download uses `practiceFileDownloaded`, which says only that the download has started and that the disk write is not yet verified, and does not use `fileSaved` or `fileDownloaded`. Opening accepts only a file that passes this mode's `validate` and differs from the current practice board, and the success hint is `practiceFileLoaded`. Cancelling, a permission refusal, corruption, more than 262144 bytes and cross-mode files do not advance, and a download is not afterwards described as a verified disk save. Neither chapter calls the real `saveFile` / `openFile`, writes `fileHandleRef` or writes the real file IndexedDB. Opening in the quantity page does not restore the edit history, and geometry adds no edit history. The factories are chained after `createQuantityNotesChapter` and `createGeometryAdjustChapter` respectively, and verified by [tests/practice-quantity-files-bundle.test.js](<../tests/practice-quantity-files-bundle.test.js>) and [tests/practice-geometry-files-bundle.test.js](<../tests/practice-geometry-files-bundle.test.js>).
- The geometry adjust and restore chapter `geometry-adjust` ([src/geometry/geometry-adjust.js](<../src/geometry/geometry-adjust.js>)) covers G17–G20. Its steps are `adjust-grid / adjust-snap / adjust-undo / adjust-redo / adjust-zoom / adjust-scroll / adjust-fit / adjust-clear`. Grid and snap each must actually be toggled first and then a new point committed in the matching state; flipping the switch alone does not count, and no geometry relation is judged from where the point was placed. Undo and redo must land on that one new point, and unavailable buttons do not count. The zoom number must change, then the view must be scrolled while not at 1× or not fitted, and then returned to the fitted view; no change in the current level or position does not count. A confirmed clear clears only the practice geometry board and its undo history, and it cannot be undone afterwards; it does not call the host quantity clear and adds no geometry edit history. The factory is chained after `createGeometryEditChapter` and verified by [tests/practice-geometry-adjust-bundle.test.js](<../tests/practice-geometry-adjust-bundle.test.js>).
- The teacher demo short guide `teacher-demo-basics` ([src/teacher-demo/teacher-demo-practice.js](<../src/teacher-demo/teacher-demo-practice.js>)) covers D01–D04. Its steps are `demo-read / demo-view / demo-copy / demo-return`. It starts only when the teacher page already has at least one figure; continuing, scrolling after changing the zoom number, pressing "Put into my geometry board"（放到我的几何画板） and then viewing the editable copy on the geometry page pass in that order. Copying uses `placeFigure` to append to the guide's own practice frame and does not call `onCopy`, `copyToGeometry` or `appendFigure`. Progress is written only to `baicai-edu-math-board:practice:v2:teacher-demo`, does not write the quantity or geometry practice keys, and does not treat `geometry-demo-seen` as completed, skipped or in progress. The "View tutorial" at the bottom right of the demo page is the permanent entry for this short guide (`teacherDemoTutorial`) and is hidden while the guide is open; with no figure it only hints `teacherDemoTutorialNoFigure`, starts no guide and writes no progress. The factory is inlined by [build.mjs](<../build.mjs>) but does not enter `quantityPracticeChapters` or `geometryPracticeChapters`. It is verified by [tests/practice-teacher-demo-bundle.test.js](<../tests/practice-teacher-demo-bundle.test.js>).
- [geometry-view.js](<../src/geometry/geometry-view.js>)'s `PracticeBoard` reuses the geometry editor, with `practice` fixed for its lifetime; the real page stays mounted and keeps responding to legal host changes. The geometry practice frame is `{board,history:{past,future},selection,tool,pending,construction,auxiliary,grid,snap,zoom,fit,scroll:{left,top}}`. Practice disables real draft persistence, file memory and input box access; only the `geometry-files` chapter may save and open practice files, and it still remembers no real file handle. Host clear / settings apply only to the real page. After exit, completion, switching pages, closing and refreshing, the real draft is still the default, and only entering explicitly again restores.
