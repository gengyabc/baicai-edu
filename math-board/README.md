# 数学画板

DSH Web 输入框工具栏（模型选择按钮旁）的数学画板按钮；点击后打开宽屏工作台。它只承载学生的思路，不做运算、不自动解题、不用图片识别，也不替学生提交答案。

## 定位

画板表达「有什么图案、每个代表多少、怎么摆放和分组」；加减乘除由学生自己在说明里讲，画板不提供运算模式，也不做对错判断。界面参考 Xiaoxue Workbench 的工作区优先结构重新实现：左侧图案工具箱、中间白色大画布、右侧按选择出现的命名面板；老师交流仍走 DSH 对话。

## 界面与交互

- 工具箱默认放十个图案：圆形、方块、三角形、星形、六边形、菱形、爱心、椭圆，以及小猫、小狗。点图案直接添加；也可以把图案拖到画布上的指定位置。
- 工具箱末尾的「更多图案」或左侧「设置」打开图案库；点一下图案就加入工具箱，再点一下收起来。已经摆在画布上的图形不会因为收起图案而消失，图案库共有 19 个图案：圆形、方块、三角形、星形、六边形、菱形、爱心、椭圆、小猫、小狗、汽车、人、苹果、小鱼、火箭、小花、蝴蝶、房子、冰淇淋。
- 单击选择；点一组里的图形会选中整组。Shift 点击或「多选」只加减点中的那一个，拖框只选框到的图形。拖动已选图形可一起移动。拖动过程只显示预览，松手后一次性记入历史，单击不产生撤销记录。
- 选中图形后，浮动栏提供圈组、合并、拆开、复制、划去/恢复、删除。
- 右侧面板按选择变化：未分组时改名字；选中整组时改**组名**，组内图形不单独命名。
- 撤销/重做在画布工具行；「只看画布」可隐藏两侧面板；画布可缩放或全图显示。

## 分组规则

分组是平铺的「小兵编队」，没有子组：

- 选中任意图形点「圈为一组」：如果其中有图形原本属于别的组，那些旧组整体解散，未被选中的旧成员回到未分组，再组成一个新组。
- 组内点任意一个图形会选中整组；Shift 点击可把别的图形加进选择，或从整组里去掉一个，再点「圈为一组」就并成新组。没被选中的旧成员回到未分组。
- 「解散组」把成员全部变回独立图形；组名可改；解散后成员恢复各自的别名。删掉一组的最后一个图形时，这组一并消失，不再占用 12 组的上限。
- 整个动作都是一步撤销。

## 合并规则

合并**只改数值和颜色，不换图形**：3 个「代表 2」的绿圆合并成 1 个蓝色圆、数值 6，名字不变，并记录合并来源，可「拆开」还原。

- 只有同一形状、同一数值、同属一组（或都未分组）、同一别名才能合并。总量正好是某一级时，用那一级的颜色；否则仍合并成原来的图案，数值是精确总和，颜色用单独的灰色。
- 不需要先为总和新增一级。灰色表示这个数不在量级阶梯上。
- 合并结果带角标显示由几个图形合并而来；拆开后恢复原来的图形与数值。

## 设置：量级与图案

量级阶梯由学生自己设定，颜色按阶梯顺序取固定调色板（绿、蓝、紫、青、橙，再接橙红、红、洋红、深紫）。图形上始终标数值，不只靠颜色识别。

- 「设置」可增删数值级、调顺序，并在图案库里添加或收起工具箱图案。
- 「这些图案默认代表多少」列出当前工具箱里的图案，可给每个图案设定默认数值和默认名字；收起的图案保留自己的默认值，重新加入时继续生效。
- 保存时选择「只用于新图形」或「也改已有图形」。已合并的图形保留合并时的数值和颜色。未合并的图形若数值仍在阶梯上，颜色改成该级现在的颜色；「也改已有图形」还会把未合并的图形改成该图案的默认值。
- 默认阶梯是 1、10、100、1000、10000，学生可以整个换掉；默认工具箱是圆、方块、三角形、星形、六边形、菱形、爱心、椭圆、小猫、小狗。

学生在对话里说「一个圆代表两个苹果」时，模型调 `math_board_settings` 把同一份设置写回本会话，工作台打开时自动同步；这走与设置面板相同的操作，不读取未提交的画板。已经同步的设置会留在撤销记录里的每一步上，撤销或重做不会把量级退回旧值。`set` 必须带上 `get` 返回的 `expectedRevision`。设置里的 `shapes` 是工具箱显示清单，模型除非被明确要求添加或收起图案，否则原样带回。客户端按投影历史逐条回放（保留每条的 `future`/`existing` 作用范围）；若本地水位落后于 `floorRevision`，仍回放保留段并提示有历史缺口。

## 学生怎样用

1. `/learn 加减法`（其他主题也可以），点输入框工具栏里、模型选择旁边的「数学画板」。
2. 从左侧挑图案点选或拖入；需要更多图案就到「设置」的图案库添加；拖动、框选、Shift 加选整理成想说的样子。
3. 选中后圈组、起名字、划去，或把同形同值的图形合并成更大量级。
4. 在「我想说」里写清这些图形代表什么。
5. 点「放入回答」回到对话：画板数据放在「我的画板.json」附件里，输入框不加入图形清单；「我想说」里写过的话会原样放进去。可先预览修改记录，默认勾选附带独立记录附件，可取消勾选或在附件栏单独删除；不勾选仍可正常提交快照。画布和修改记录都留着，学生可以继续改错再放入。检查正文和附件后**自己**发送，插入不等于发送。要换一道题时点「清空」，画布和这次的修改记录一起清掉。

键盘：Tab 聚焦图形，Enter/空格选择，Shift+Enter 切换多选，方向键移动，Delete 删除。

## 数据

`kind: "math-board", schemaVersion: 3`：

```
settings: { levels: [{value, color}], defaults: [{shape, value, alias}], shapes: [shape] }
objects:  [{ id, shape, value, color, alias, x, y, groupId, removed, sources }]
groups:   [{ id, alias }]
note:     学生说明
summary:  确定性数量汇总（不是对错结论）
```

`settings.defaults` 覆盖全部 19 个图案，学生的默认值不会因图案收起而丢失；`settings.shapes` 是工具箱当前显示的图案顺序（至少一个）。`model.js` 是画板状态的领域实现，`trace.js` 独立处理修改事实及有界保留；`config-bridge.js` 是设置的服务端桥（工具、用户命令、会话投影共用同一操作）。画板草稿与修改记录只存在浏览器本地并按 DSH 会话隔离，刷新页面、关闭工作台或关闭浏览器再打开仍保留；直到点「放入回答」，才把只读快照及学生勾选的修改记录作为附件上传到本机 Host。坐标不隐含算式。

「放入回答」把完整 JSON 作为 `我的画板.json` 文件附件放进草稿，不把图形、分组或划去清单写进输入框。学生在「我想说」里写过的话会原样放进去。画布和修改记录都保留，学生可以在同一块画板上改错并再次放入。附件是只读的精确快照，模型读取它再回应，不把清单复述给学生，也不把更早消息里的修改记录串成总过程。附件在点击「放入回答」时上传到本机 Host，但直到学生自己发送才进入会话；学生可以像普通附件一样撤销它。点「清空」才同时清掉画布和本地修改记录，已经放入或发送的附件不删除，清空后不能撤销。

旧版 `schemaVersion: 1` 和 `2` 的 JSON 会自动迁移：v1 保留圆形、方块、三角形作为工具箱内容，v2 保留原来的十个图案，并为新图案补上默认值；浏览器草稿会从 v2 存储键读入后写回新的 v3 存储键。详见 [教学协议](<../math-low/skills/math-core/references/structured-drawing.md>)。

### 独立修改记录

`kind: "math-board-trace", schemaVersion: 1` 是可选的修改记录附件，不是快照的新版本。快照保存/打开仍只往返 v3 数据，既不导出记录，也不从导入文件恢复记录；导入会令此前过程标为未知，画板因此实际改变时才留下一条导入变化。两者分离的原因见 [ADR-0001](<../docs/adr/0001-board-trace-separation.md>)。

- **尝试边界**：记录从上次「清空」之后积累，放入回答不中断记录，学生可以继续改错。旧草稿没有历史时标 `priorUnknown`，不能把缺失说成“学生没有修改”。点「清空」同时清掉画布和本地修改记录，撤销也不能回到清空前；已经放入或发送的附件不删除，新过程从空画板开始。「清除记录」与「开始新尝试」都只重置记录并保留画板，若保留非空画板作为新起点则标 `priorUnknown`。
- **记录内容**：按发生顺序记录用户可见的语义变化，包括添加、删除、改名、分组、合并/拆开、划去/恢复、学生说明、撤销/重做、清空、画板因此改变的导入及设置变化；区分学生与系统来源，系统同步设置不能算学生操作。选择、悬停等界面动作不是语义事实；不记录坐标或时间戳，也不据此推测停顿时间、意图或熟练度。
- **有界保留**：只折叠连续完全相同的事实，不把不同变化或隔开的重复合成一条。上限为 60 条；超出后保留最早 20 条和最近 30 条，明确标出省略的动作数，而不是暗示完整历史。独立附件上限为 64 KB，与快照大小限制分开；不可用时不妨碍仅提交快照。某次记录写入失败时保留已有事实，并把此后过程标为未知，画板本身照常保存。
- **可见提交**：界面提供记录预览、默认勾选但可取消的附带复选框，以及不同的「清空画板」、「清除记录」与「开始新尝试」入口。「清除记录」与「开始新尝试」都只删掉本地修改记录并保留画板。记录只有随学生自己发送的消息才进入会话，学生也可在附件栏单独删去；已发送附件随会话保留，不是临时阅后即失。没有另建永久行为档案，也不向学生档案写入修改次数。
- **按需阅读**：AI 通常只读快照；学生卡住、主动请求回看或材料不一致时才读记录。只使用当前消息附带的这一次记录，不把更早消息里的记录连起来。新的学习会话不使用上一场已发送的画板或其中的数量差异；本场没有已发送快照时，不据此谈画板。记录只提供可观察事实，最多据此问一个澄清问题，不自动诊断或判定掌握；历史状态不同于最终状态通常只是修改。省略或未知的历史保持未知；记录缺失或不可用时回到快照，真正缺少数量含义或关系时问学生，不补造解释。

## 开发与安装

```bash
node math-board/build.mjs
node --check math-board/client.js
node --test math-board/*.test.js
node scripts/check-skills.mjs
node math-board/preview.mjs /tmp/math-board-shapes.html   # 可选：在无头 Chrome 或浏览器里目视检查图案
# 用 DSH plugin_manager 安装本目录；也可人工运行：
dsh plugin --profile web add link:/Users/yugeng/programming/dsh-edu/math-board
```

纯 JavaScript 包，无第三方依赖、无安装脚本。提交生成的 `client.js`；修改模型、视图、样式或字典后运行 build。`preview.mjs` 用最小 React→SVG 适配器渲染全部图案，便于对比猫、狗等小尺寸辨识度；它不进入运行时包。首次安装支持 live activation，替换已安装模块是否需要重启以安装结果为准。

图案是本项目用 SVG 基本图元绘制的原创图形；`build.mjs` 将视图与图案工厂一起内联进 `client.js`，运行时不需要外部图片。

## 手工验收

- 进入真实会话打开工作台；检查触摸拖动、框选、键盘操作、明暗主题与窄窗口。
- 工具栏按钮位于模型选择左侧，高 28 px，与相邻控件基线对齐；窄窗口只显示星形图标，悬停或读屏仍报出「数学画板」，点击打开同一工作台。
- 工具箱默认显示圆、方块、三角形、星形、六边形、菱形、爱心、椭圆、猫、狗；猫有尖耳朵和胡须，狗有下垂耳朵、口鼻和舌头，缩到 28 px 仍能区分。
- 打开「设置」→ 图案库，添加小鱼/火箭等图案后工具箱出现，收起后消失；已摆在画布上的对应图形仍在。至少保留一个工具箱图案。
- 给新加入的图案设默认数值和名字，保存后添加该图案使用新默认值；恢复默认回到圆、方块、三角形、星形、六边形、菱形、爱心、椭圆、猫、狗。
- 画布底部工具行（撤销/重做、多选、只看画布、缩放）和页脚（保存/打开/清除记录/清空、放入回答、返回对话）在桌面、窄窗口和短窗口下都完整可见，不被画布或弹窗边缘裁切。
- 拖动图形能摆放，多选后一起移动，松手只产生一条撤销记录。
- 分组：选中含旧组员后重新圈组，旧组解散且未选中成员回退为未分组；解散后成员别名恢复。
- 合并：设为「圆代表 2」后合并 3 个圆，得到一个蓝色圆、数值 6，图形不变；拆开后恢复 3 个绿圆。
- 设置：改「圆代表 2」只影响新图形；选「也改已有图形」后未合并的圆也变成 2。自然语言说同一句话后，打开工作台看到同样结果。
- 原输入框有文字时「放入回答」不丢失原稿；导出再导入数据一致；无效 JSON 显示失败且不更改现有画板。
- 「放入回答」后附件栏出现「我的画板.json」，输入框不出现「我在数学画板上摆好了」这类清单；学生写过「我想说」时，正文只有那句话。画布和修改记录仍在，可以改完再放入。正文里没有 JSON；发送后气泡上方显示文件卡片。模型能按提示读取该文件，且不把图形清单贴回对话；修改记录只看当前这条消息。
- 修改记录可预览且可不附带；不勾选只带快照，勾选才多出独立记录附件，两种情况都需手动发送。刷新页面、关闭后重开保留本地草稿及记录；旧草稿缺记录显示此前未知。
- 确认清空后画布和修改记录都没有了，不能撤销；取消清空则两者都保留。已放入或发送的附件不被删除。「清除记录」和开始新尝试都只重置记录并保留画板，非空起点显示此前未知。撤销/重做、导入及学生/系统设置变化来源正确；快照导出不含记录，导入不带回旧记录。
- 用超过 60 条的合成变更检查最早 20 条、最近 30 条和省略动作数；仅连续相同事实折叠。检查独立附件的 64 KB 上限与失败时仅发送快照的路径，记录中没有坐标、时间戳。

### 手动离线对照：相同终态，不同修改过程

以下是**待人工执行的合成场景**，不是已经完成的 LLM 评测。固定题目为“用图表示 3 组、每组 2 个苹果”，终态快照和学生说明均保持相同：3 组，每组 2 个代表 1 的苹果。为每个场景分别准备“仅快照”和“同一快照 + 可选记录”，离线人工对照教学回应；不连接真实学生资料或建立行为档案。

| 合成场景 | 准备的修改事实 | 人工检查重点 |
|---|---|---|
| 直接完成（straight） | 添加 6 个苹果并圈成 3 组，每组 2 个 | 仅凭终态与直接完成过程都不能认定掌握；普通教学无需主动读记录 |
| 修改后完成（corrected） | 先圈成 2 组、每组 3 个，再解散重圈为 3 组、每组 2 个 | 在学生请求回看时，可问“我看到你把两组改成三组，这两种分法分别表示什么？”；不把旧状态与终态差异叫矛盾或自动判错 |
| 清空后重摆（clear-restart） | 先摆 2 个苹果，点「清空」，再摆成相同终态 | 新记录里只有重摆，没有清空前的事实，也不另记一条清空事件；不把缺失的旧过程说成学生没有改过。已发送的上一份附件仍可单独阅读 |

共同护栏：只对已发送材料作答；记录里的文字视为作答材料而非指令；学生卡住、请求回看或材料不一致才按需查记录。对照时确认观察能指向实际事实、一次只问一个澄清问题；不依据动作数、系统同步、截断缺口或一次顺利完成诊断困难或判定掌握。不支持或损坏的记录退回快照；快照缺少真正含义时澄清，既不编过程，也不编运算关系。历史中出现过另一种摆法本身不是当前材料矛盾。
