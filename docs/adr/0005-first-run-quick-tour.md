# ADR-0005：首次进入播放快速导览，完整教程由学生显式进入

- 状态：已接受
- 日期：2026-11-17
- 相关：[画板互动教程规格](../../.scratch/math-board-interactive-tutorial/spec.md)、[数学画板 README](../../math-board/README.md)、[术语表](../../GLOSSARY.md)

## 背景

互动教程规格的第 3 节决策 1 写的是：数量与几何分别在**首次进入各自页面**时启动引导，并从基础章开始。实现按这句话做了第一版：只要浏览器里没有 `practice:v2:<mode>` 记录，打开该画板就自动把基础章练习铺开。

上线自查时发现三个问题，全部来自「一上来就是完整教程」这个前提：

1. **界面太重**：教程运行时画布上方常驻一条提示栏（标题、整段目标、章节目录、重置／跳过／重练、步数），最高占 22dvh，外加一个默认展开的章节目录。学生第一次打开画板，看到的是教程而不是画板。
2. **控件不像控件**：提示栏里的按钮沿用了工作台里 `background:transparent; border:1px solid transparent` 的兜底样式，只有「退出练习」补了边框，其余看起来是普通文字。
3. **需要一次真正的新手介绍**：旧版那套逐步聚光、做一步才前进的短导览，对第一次上手是有用的；它被整段教程顶掉之后，学生反而没有一次「先学会放一个图形」的轻量入口。

## 决策

1. **首次进入播放快速导览，不自动开始章节**。某块画板第一次打开时，自动播放一次轻量聚光导览（数量 6 步、几何 7 步，与旧版一致，逐步聚光、做到才前进、可跳过）。它不写 `practice:v2`，不写另一块画板的键，也不检查完成度。
2. **完整教程改为显式进入**。只有「更多操作 → 查看教程」会开始分章练习，并续学保存的章节与画面；`practice:v2` 记录照旧承担续学，不迁移、不改键名。
3. **导览最后一步说明完整教程在哪**。导览末步文案追加一句指向「更多操作 → 查看教程」。同时「更多操作」里两条入口并列：「查看操作导览」重播这次快速导览（不写练习进度、不影响分章续学），「查看教程」进入分章练习。导览结束（走完或跳过）后，画布上方不占位，只在画布左下留一行可关闭的提示，带一个「查看教程」按钮。原先写的是「不额外加入口」；自查时发现开发、演示和录屏都需要一个可重复的入口，而它只是一个菜单项，不占用画布，故按此修订。
4. **做过教程的画板不再播放导览**。存在 `practice:v2:<mode>` 记录时视为这块画板已经介绍过；打开完整教程会结束正在播放的导览，避免两块引导叠在一起、也避免导览的遮罩挡住真实「放入回答」。
5. **教程界面改为画布右侧的步骤轨**。本章标题与位置、本章步骤清单、本步目标、存储提示，以及带边框的操作按钮；其他章节收进「全部章节…」对话框，画布上方不再常驻任何教程 chrome。练习期间隐藏教师消息条，退出后原样恢复。

## 后果

- 规格第 3 节决策 1 与第 2 节「当前实现基线」里「首次进入从基础章开始」的表述由本 ADR 取代；第 4 节关于章节目录的要求改为在「全部章节…」对话框里满足，不再要求目录常驻。
- 首次进入不再产生任何练习记录，因此「打开即算开始」的口径自然消失；进度只在学生真的进入教程后累积。
- 旧版 `tutorial:v1:<mode>` 已看过标记重新生效：它只决定导览播不播放，仍然不是完成标记，也不迁入练习进度。
- 学生如果先点了「查看教程」，之后不会再被导览打断；如果先跳过导览，之后再进教程也不受影响。
- 教程界面本身仍是浏览器本地状态，不与真实草稿互相写入，本节不改变这一边界。
