# 小学数学主动教学与历史推荐改造计划

## 1. 入口决策

**新授和历史推荐都并入 `/learn`。保留 `/learn-start`，不新增 `/teach` 或 `/recommend`。**

当前归档中的实际命令为 `/learn-start` 和 `/learn`。前者选择或切换学习者、学科和目标，激活档案，随后把教学交给 `/learn`。后者已经能从话题、材料、错题或档案目标进入统一的会话生命周期，再经 resolver 交给当前学科的 session。主动教学应复用这个路径。学生侧可以说“教我……”，无需理解什么是微课或选择低段、高段包。

| 层 | 职责 | 本次边界 |
|---|---|---|
| `/learn-start` | 身份、学科、档案激活，可承接目标 | 不讲课，不新增“主动教学”配置卡或档案偏好 |
| `/learn` | 接收本轮目标或继续意图，进入 lifecycle | 可更新帮助示例，不写数学选法，不绕过当前学科 resolver |
| Lifecycle / resolver | 处理恢复、结束、换题、材料、目标和学科路由 | 增加受限的数学冷开场推荐条件，复用推荐选择、保存与恢复，不判断教学方法 |
| `learn-recommend` | 组织历史候选、呈现理由、等待选择 | 复用现有模块。学科规则决定推荐什么，数学 session 决定怎么开始 |
| `math-low-session` / `math-high-session` | 判断同一目标下应新授、引导、诊断还是练习 | 新授由本 session 执行，其他活动照旧 |
| `math-common` | 给两个学段共用的微课规则 | 仅提供规则，不执行学生回复、不跨调度、不写档案 |

**关于 start 传递意图。** 归档中的 start 激活规则没有明确把新授意图写进下一次空参数 `/learn` 能读取的持久状态。MVP 不依赖这种传递。若用户在 start 说“想学通分”，激活后提示可直接输入“教我通分”；支持命令带参数的界面可显示 `/learn 教我通分` 示例。将来若确实需要 start 预选后空参数续接，再单独设计一次性意图交接，避免把临时意图变成长久偏好。

## 2. 路由规格

路由优先级按语义判断，不把“教”“讲”当正则开关。仅在进入新目标、明确请求同目标切换，或已有明确支持证据且学生愿意改用示范时选微课。普通答题、短答、空消息不重新分类。

| 输入或状态 | 预期行动 |
|---|---|
| `/learn 教我异分母分数加法，我没学过` | 同时明确主题、意图和起点。数学 session 直接进入微课，不先出诊断题、不弹菜单。 |
| `/learn 我想学分数` | 若从已有资料能选一个合适的起点，就说明该小目标并开始。只有“初识分数 / 分数运算”等分歧会实质改变教学时，问一个短问题。 |
| `/learn 分数加法` | 主题清楚、教学意图不必然清楚。复用历史和当前状态。若学生过去已在练同一关系，不把它重置为新授；若选择会实质影响下一步而没有证据，可问“你想先看一个例子，还是先试一道？” |
| `/learn 给我三道分数加法题` | 走现有 practice，遵守其按目的出题及题量规则，不强制先看示范。 |
| `/learn 我想自己推平行四边形面积公式` | 继续 derivation，保留关键推断，不能因为有“公式”或“学”就先给结果。 |
| 有一道原题待答，学生说“讲讲这一步” | 留在原题的当前障碍，按既有支架规则处理。 |
| 有一道原题待答，学生说“我没学过这个方法，先用另一道题教我” | 原题保留，允许同目标的短示范。MVP 可只在无需复写原题状态时做单轮类比示范，之后回原题的原待答点。不要把这条做成换题或递归计划。 |
| 有一道原题待答，学生说“直接给这题完整解答” | 走现有同题知情选择，不能改走微课来交付原题解答。 |
| 空参数 `/learn`，有未完成活动 | 恢复现有题或微课。没有未完成活动、明确目标或已选择候选时，数学进入历史推荐。推荐后不自动新授。 |
| Feynman、暂停、结束、换目标或等待保存 | 保留 lifecycle 优先级。微课不能抢占学生讲述角色或跳过保存。 |

**主题与动作分开。** 只在 lifecycle 本来就做目标解析的场合，让高低段 `math-target.md` 从自然话中提取主题，保留学生主题原话的关键内容，不改成图谱 ID。可用既有 `target_context.intent` 保留明确的新授请求的原话，不覆盖错题和附件链路已保存的原始意图。它只是输入线索。是否进入或继续微课由数学 session 判定，不能仅靠 intent 字符串触发。已恢复的会话直接读取最新消息和待答点，不为同目标的动作重跑目标解析或生成新 `scope_id`。

## 3. 历史推荐怎么接入

当前包已具备 `learn-recommend`，低、高段各有 `learning-recommendations.md`。现有规则会读历史、给 2–3 个候选、标一项首选、等学生选定。真正缺的是两段：**什么时候无须学生先说“推荐”就展示候选，以及选中后如何把理由变成合适的教学起手。**

### 3.1 触发与优先级

按 lifecycle 原有顺序，先处理必须优先的恢复、结束、暂停和明确请求，再使用下列产品规则：

| 场景 | 行为 |
|---|---|
| 已有待答题、微课或先修计划，只输入 `/learn` | 继续当前任务。不要用历史推荐覆盖它。 |
| 学生明确指定目标，或从 start 已可靠带入确定目标 | 直接进入教学。不先显示推荐。若 start 没有实际传来目标，不猜。 |
| 学生说“今天学什么”“换个内容但没想好”，或点击“换内容” | 复用已有推荐入口。展示时保留原题。只在学生选定不同目标后执行现有切换和保存。 |
| 本轮空参数明确开始数学学习，已有可用身份，没有未完成任务、未选完的推荐、明确目标或已授权目标 | **新增默认推荐。** 把档案原先会自动取用的 `next_step` 当候选，不自动开教。首次没有历史，给探索候选而不是伪造诊断。 |
| 已有未选择的推荐，学生再次输入空参数 `/learn` | 恢复同一批候选，不重新排序。空消息、跳过都不授权首选。“你帮我选”按现有委托规则采用首选。 |
| 学生只想聊天、结束，或仍在 Feynman | 不因数学冷启动自动推荐或切模式。显式推荐请求维持原有 Feynman 规则，选中后仍由学生主讲。 |

实现上，在 lifecycle 既有 recommendation gate 内加一条数学专用条件，位置在确定当前身份、恢复状态和显式目标之后，在普通 profile 候选兜底之前。只对已解析为数学专项且处于普通学习的冷开场生效，不改变通用教学或其他学科。避免新建一个并列推荐入口。

### 3.2 用什么证据，怎么排

只用现有 snapshot 和当前真实表现。基线只保留最近 5 个会话摘要和 20 条近期错题，摘要不是逐轮日志，旧记录可能未保留提示条件。只在记录明确写出时使用“独立”“受助”“延迟”等判断。缺少条件就留未知，不扫描原始材料或旧会话去补齐全量历史。

| 看到的证据 | 推荐候选 | 建议起手 |
|---|---|---|
| 多条相符表现显示一个具体关系不稳，或现有诊断已确认 | 修补最小的相关缺口。例如“用同一个整体看懂等值分数” | 缺口清楚可建议短示范。原因仍有歧义时，先做一项有区分力的探查。 |
| 最近跟着提示完成，仍无独立证据 | 巩固同一关系，不直接推荐更难内容 | 用新题做无提示检查，必要时再给支架。 |
| 最近在可比任务中已独立理解或选法 | 推荐一项近邻新知、结构变式或迁移 | 新知用微课，迁移用不暴露方法的新题。高段最多先看已有图谱的一条相关边，低段用既有进阶线索，不遍历整张图。 |
| 已有明确的以后复查建议，或历史显示该关系曾会但近期还没见到表现 | 提议用一题回看，不声称“已经遗忘” | 直接给无提示的新题。没有可比较日期或记录时，不宣称“到期”。 |
| 只有一次错题、只有年级或兴趣、只有学生自述 | 单次错题可支持局部澄清。年级和兴趣只帮助选择低门槛入口。自述可以试用但不当作掌握 | 轻量探索或按学生明确目标开始，不先做一整套测验。 |

排序用规则即可，不加分数模型：

1. **先限定范围。** 学生明确要换内容时，优先找不同关系或领域，不把旧题换名字排第一。已有可靠的目标时直接教学。
2. **再处理证据冲突。** 最新、可比的独立证据可以替换过期建议。不同任务、提示程度或知识范围的结果不要合并成“这个概念已会”。
3. **最后选最能推进的一步。** 与当前目标有关的已证实阻塞优先。没有阻塞时，在巩固、近邻新知、迁移和已约定的复查之间，按最近证据与现有目标选一个首选。近期已独立、无复查需要的同构练习不占首位。候选通常 2–3 个，只有一个有充分理由就只给一个。
4. **理由要能核验。** 用“一条真实表现 + 为什么建议这一步”。例如“上次你能把 3/4 和 6/8 画成同样长，这次可以看怎样把两个分数写成同一种单位。”不要说“你的分数能力不足”。

### 3.3 选中后如何接到教学

候选仍使用既有的 `id / focus / target_context / reason / basis`。用明确的候选小目标和证据推导起手。不建议把“教我”写进话题名称，也不要用系统生成的理由覆盖 `target_context.intent` 中的学生原话。

- **建议最小的机器可读交接。** 若依靠小目标文本无法稳定重现选后的起手，在现有 `target_context` 内加一个数学专用、可选、仅本次开场的 `math_opening_hint`，取值 `micro_lesson`、`practice`、`probe`、`challenge`。它只是教学建议，不是授权或新全局模式。只在推荐候选与选定后的当前会话上下文中存活。旧候选没有该键时按原规则。不要向长期推荐摘要、档案、能力证据或通用学科记录写它。
- **用已有保存与恢复协议。** 推荐时仅保存候选，选定时先保存 `selected_id`。不同目标按原规则先保存旧任务，再写入新目标。写入失败不开始教学。首次成功开场时，由 session 选择真实动作，在同一次上下文写回中记录已推进的待答点并消费提示。恢复看已经记录的活动，而不是再用提示重开。不改变 finalize 的持久化策略。
- **同一目标和显式请求优先。** 推荐卡上的“继续当前”直接回待答点，不做同目标覆盖。只有学生明确要求改变同目标的学习方式时，才由当前 session 切动作并保护待答题。新消息明确说“我自己想”“只给练习”或要求完整原题解答时，优先尊重，忽略过期的起手提示。
- **推荐被选中不等于有学习表现。** 推荐卡、选择与示范都不写表现 segment。真正作答后才记录独立或受助。会话结束时，沿原有 `next_step_candidate` 留下一条有依据的后续建议，供下一次推荐使用，不另写推荐数据库。

首版不做长期遗忘曲线、复习定时、BKT/IRT 或独立推荐服务。要解决的只是：在没有明确目标时，能用已有证据给学生一个可信的下一步，且选了就能开始。

## 4. 微课怎么教

把**新授**定义为目标层的一种活动，不规定必须用显式讲授。低段可用实物、图或数轴连接单位与数量，高段可用式子、对比、构造、推导或例题。选法依据当前目标、已知基础和学生选择。能理解和应用已给公式，与独立推导公式是不同目标。

每次聚焦一个能观察的小目标，通常按以下方式推进，不设回合配额：

| 可选环节 | AI 做什么 | 可以记录什么 |
|---|---|---|
| 定目标 | 直接说明这次学什么。只在关键前提未知且会改变教法时做一个低负担探查。 | 目标、起点证据或未知项。不因年级或沉默判定缺口。 |
| 教一处 | 给短讲解、可视表征或经过验证的示范。多种表征可以同轮服务同一关系。 | 纯示范只写会话上下文，`session_segment: null`。 |
| 带一步 | 让学生承担一个真实判断或动作，不要求照抄示范。 | 跟做记为受助。可以区分执行是学生完成、选法是 AI 提供。 |
| 独立检验 | 给结构合适的全新题，不提示本轮要用的方法。学生也可以结束或改为练习。 | 只记新题实际展示的正确性、关系、策略及独立性。单题不等于长期掌握。 |

例子。小目标为“知道为什么相加的分数要用同一单位”。示范用同一条纸带讲 `1/2 + 1/4`。带做时请学生把 `1/2` 写成几个六分之一。等学生能继续，再用未提示的 `1/3 + 1/4` 检查能否自行找共同单位。如果孩子已经懂同一单位、只是不会选公分母，就直接调整小目标和例题，不再从纸带重讲。若学生只想看讲解后离开，允许结束，不强制做检验题。

**主动教学的第二个触发可后置。** MVP 先完成学生主动说“教我”时的入口。稳定后，诊断发现一个明确缺口时，可以主动提议“我可以先用一个小例子讲这一步”，得到同意再开始。已有授权的定向支架仍可直接给。不要把一次错答自动解释为需要上一课。

## 5. 改哪些文件

路径简写：`G = learn/skills/learn-core/references/`，`D = learn/skills/learn-data/references/`，`C = math-common/skills/math-common/references/`。下表的“低/高 core”分别指两段对应包下的 `skills/math-low-core/` 与 `skills/math-high-core/`。

| 次序 | 文件或位置 | 修改与约束 |
|---|---|---|
| 1 | G `pedagogy-core.md` | 在 Guide before revealing 下补新授例题例外。明确适用条件、范围和优先级。保留独立测查、约定自主推导、原题完整解的规则。数学专项是否启用由当前学科决定，其他学科不因共享规则改动而改变默认行为。 |
| 2 | C 新增 `micro-lesson-contract.md`，及 `math-common/SKILL.md` | 共用起点、选法、示范、受助与独立证据、退出与回返规则。由 band session 在分流命中时加载，其他教学不预加载。加载失败保留现有引导式主线，不声称执行了微课。 |
| 3 | 两个 `math-*-session/SKILL.md`，高段 `learn-act-allocation.md` | 在默认“先选一道题”前识别新授。同一 session 执行 `micro_lesson`，不新增 leaf、外部命令或分派者。高段新增明确的 act 和退出条件，不能并列激活另一个 act。低段复用同样的活动语义，避免复制公共流程。 |
| 4 | 两段 `math-target.md`、`math-teaching-core.md`、`scaffold-calibration.md`、`problem-design.md`，以及 core 的按需加载表 | 分离主题和意图。同步调整两段支架入口、高段显式指导方法表与例题规则。确保低段开场示范不会被“还未开始做题”拦截。 |
| 5 | 高段 `derivation-teaching.md` 和 `prerequisite-learning.md` | 复核公式新授、应用、查阅、自主推导的边界。沿用已经证实且必要的先修缺口才建子任务的原则。普通新授微课不用新建 `learning_plan`。 |
| 6 | D `session-schema.md`、两段 `math-segment-fields.md` | 仅补向后兼容的可选会话状态说明和证据归因。沿用 lifecycle 写回与单 segment。无需改持久档案、学习评分、全局 `mode` / `activity` 枚举或 finalize。 |
| 7 | D `session-lifecycle.md` 与 `learn/skills/learn-recommend/SKILL.md` | 增加数学无目标冷开场推荐条件。复用现有 gate，不另建推荐状态机。更新原有“普通入口不自动推荐”的限定，保持其他学科不变。 |
| 8 | 两段 `learning-recommendations.md`、D `target-parsing.md`、`session-schema.md` | 增加候选分类、证据排序与临时起手提示契约。高段用现有 `topic-map.md` 的邻接关系，低段用现有进阶表与任务规则。 |
| 9 | `learn/skills/learn/SKILL.md` 或 README 帮助示例 | 增加“教我 / 让我自己想 / 给我练习 / 今天学什么”。只说明入口，不在 `/learn` 本身实现数学选法。start 运行时规则维持原样。 |

共享门槛可采用这段英文规则草案：

> For an explicitly agreed new-learning goal, the subject may use a brief, verified and labeled teaching example when learner report or observed evidence supports teaching the target relation or method. No failed attempt is required. If a learner-owned problem is pending, demonstrate on a separate item without supplying the original answer or its decisive inference. Preserve the original problem and resume it at the appropriate step. This does not bypass independent assessment, agreed discovery, or the informed full-solution choice.

### 状态方案

- 继续使用 `mode: learn`、`context.activity: teaching` 和已有 `submode: learn`。高段复用 `context.turn_state.active_act`，低段仅在微课中使用相同的可选 act 标记。这样微课仍属于现有教学，不新增生命周期状态。
- 如果现有 `current_task`、`pending_question` 和已呈现支持不足以恢复，才增加一个数学局部可选块 `turn_state.micro_lesson`，最少保存 `goal`、当前 `phase`（`example` / `guided` / `independent`）与已暴露的关键支持。原题、答复、待答问题仍由现有字段持有，不双写。同目标原题上的单轮示范不需要保存第二道待答题。
- 恢复用原会话、原题及待答点。转练习或退出微课时清除局部活动标记。学生切换模式、暂停或换目标继续走现有 lifecycle。旧记录没有微课状态时按原路径恢复，不猜测学生曾同意新授。
- 只有学生真正做了数学动作才生成学习证据。AI 解释、学生选择活动、空消息都不写表现。受助与独立仍进入同一套现有字段。新功能不引入 BKT、IRT 或新档案字段。

## 6. 实施批次与发布门槛

**批次一，先打通高段的端到端主链。** 写共享门槛和微课契约，接入高段历史候选和选后起手。先验收「无目标进入 → 历史候选 → 选定 → 示范、复习或挑战」，再用显式目标、自主推导和练习请求验证不误触发推荐。

**批次二，接入低段并补兼容。** 用数的组成或等号关系验证低段。同步低段推荐与加载规则、两个学段的证据记录说明。跑普通帮助、跨会话恢复、旧候选、附件、Feynman 和换目标回归。

**批次三，按实际使用决定是否加入口按钮。** 默认只支持自然语言。不改基础菜单四项。如果孩子经常不知道可以让 AI 先教，再给两个数学包加本地化的学科额外项 `ui.stage.math_micro_lesson`。它只在已经有可教目标、且没有待答冲突时出现。按钮和自然语言走同一个 action，中文与英文键写在数学 core 的 locale 文件。可晚于核心能力上线。

| 验收场景 | 必须观察到的行为 |
|---|---|
| 同主题输入“教我，没学过”“我想自己推”“给我练习” | 分别为短示范、保留关键推理、直接呈题。三个开场不能只是换说法。 |
| 低段新学等号含义 | 适龄的对比或表征解释，不被默认生活题格式或支架加载门槛拦住。 |
| 纯示范、跟做、新题独立完成 | 依次是无表现 segment、受助表现、独立表现。 |
| 有原题时要局部讲解、看另题示范、要原题完整解 | 三种分流互不混淆。前两种不交付原题完整解。 |
| 用空参数 `/learn` 继续微课 | 接回原来的待答点，不重讲开场、不新建 scope。 |
| 显式切换到练习、Feynman、暂停或结束 | 保持原有切换和保存规则，不让微课抢占。 |
| 空参数新开数学且有历史，没有已选定目标 | 先给少量有具体理由的候选。看完、沉默或跳过均不自动选第一项。 |
| 历史建议曾是“练等值分数”，最新同范围独立证据表明已会 | 可将通分排在重复练习之前。若最新证据只覆盖更简单的情境，不覆盖旧缺口。 |
| 只有一次错题、只有受助完成、没有历史，各一例 | 分别产生低强度澄清、独立复习建议、明确的探索候选。不报已掌握或稳定薄弱。 |
| 推荐选中后写入失败、重新进入 | 保存的 selected_id 保留。成功前不教新目标，恢复后只执行一次。不重复出推荐卡。 |
| 旧日志、旧错题输入和非数学教学 | 旧记录不迁移，原有处理路径不改变。 |
| 已会学生拒绝示范或中途不想继续 | 尊重选择，允许转练或结束，不扣阶段、不写假证据。 |

测试建议分别加在 `learn/tests/guided-teaching-scenarios.md`、`math-common/tests/teaching-scenarios.md` 和两个 band 的 `tests/teaching-scenarios.md`。先验证同题不同意图、原题保护与证据归因，再检查微课讲解质量。运行时回归通过不能代替学生学习效果验证。

## 实施边界

这份计划基于已上传的 Skill 快照。未改动原包，也未执行上述回归。首版成功条件是：**同一个 `/learn` 入口既能根据证据推荐学什么，也能在选定后采取与目标匹配的第一步。继续原题、主动指定目标、自主推导和练习不被推荐或新授抢占。**
