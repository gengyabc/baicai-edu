## Agent skills

### Issue tracker

Issues are tracked as local markdown files under `.scratch/<feature>/` in this repo. See `docs/agents/issue-tracker.md`.

### Triage labels

The five canonical triage roles keep their default label strings, recorded as a `Status:` line in each issue file. See `docs/agents/triage-labels.md`.

### Domain docs

Single-context: one `GLOSSARY.md` at the repo root plus ADRs in `docs/adr/`. See `docs/agents/domain.md`.

## Education skill packages

- Install education bundles with `node scripts/install.mjs <package|all> --profile web`; dependencies come from each package's `package.json`. For installation, dependency changes, or disabled-bundle recovery, read `docs/installation.md` first; current DSH does not auto-enable transitive bundles.
- User-only entries (`learn-start`, `learn`, `learn-clean`) set `disable-model-invocation: true`; their only entry is the user's `/name`. `learn-clean` previews and confirms cleanup; ordinary cleanup preserves identity, originals, and raw backups, and the safe-high row keeps those while discarding only the student's records. Its high-risk complete-deletion branch requires a separate scope confirmation and typed confirmation phrase; see its `references/high-risk-deletion.md`.
- In-conversation entries (`learn-feynman`, `learn-profile`, `learn-save`) stay model-invocable so the model can load them from a student's intent, while remaining user-invocable via `/name`.
- Internal skills loaded by another skill must stay model-invocable: use `user-invocable: false`, never `disable-model-invocation: true`, because DSH has no separate skill-to-skill channel.
- Skills are addressed by name; shared rules live in `learn/skills/learn-core`, the student-data protocol in `learn/skills/learn-data`, error-file handling in `learn/skills/learn-errors`, and image reading in `learn/skills/learn-read-image`.
- Math ships two band packages with unique skill names: `math-primary-low` registers `math-low-*`, and `math-primary-high` registers `math-high-*` (including `math-high-application-modeling`). For new tasks, explicit grades 1–3 prefer low, grades 4–6 prefer high, and a missing grade defaults to low; these are teaching defaults, not content gates. Record actual core/session names in `teaching` and keep an unfinished task's band. Selection and legacy-name restore follow `learn-data/references/teaching-resolver.md`; no host patch is required. Method provenance lives in `docs/math-primary-high-methods.md` (teaching material, not installed skills). Both bands depend on `dsh-edu-math` (directory `math-common/`), which registers only internal `math-common`: shared contracts for agreed micro-lessons, student-authored problems, practice evidence, the board, and handwriting/image reading. It supplies rules, never a teaching implementation or resolver candidate; band differences stay local. See `docs/adr/0001-math-shared-contracts.md`.
- Handwritten or photographed work is read by internal `learn-read-image` in `learn`, loaded only when a message or file actually carries an image. It transcribes without silently correcting, marks ambiguities, archives the original, writes the reading record, and returns evidence and at most one pending question to the current teaching owner; it never diagnoses, speaks to the student, or writes the profile. Math reading hints and deterministic step-check facts live in `math-common`'s fourth contract, which both bands load before the reader; no grade-specific supplement is kept. See `docs/adr/0002-handwritten-image-reading.md`.
- Unknown learning goals **when the student asks what to learn or accepts an invitation**, explicit recommendation requests, the stage action `ui.stage.switch_content`, and the lifecycle's restricted bare-`/learn` math cold opening load internal `learn-recommend`; subject contracts own recommendation pedagogy. Pure support or ordinary chat with no learning request does not auto-recommend. Process UI copy and recommendation reasons use the active UI locale from `profile.language` via `learn/skills/learn-data/references/ui-locale.md` (catalogs under the owning core skill’s `references/locales/`). Pending choices are temporary log state, not teaching evidence or task-switch authorization.
- Student system state is written under `outputs/students/`; user-provided originals live under `data/students/<id>/<subject>/raw/`. Both `outputs/` and `data/` trees are gitignored. Do not commit them or expose raw student JSON to the student.
- Per-turn session state goes to `session_log.json`; `profile.json` / `memory.json` / `milestones.json` are written only at finalize. `current_state.last_finalized_session_id` is the idempotency marker.
- `personal.interests` in the shared `profile.json` is the cross-subject personalization field; Chinese, math, and English skills must read it. Subject preferences and easy/hard topics live in the subject profile.
- Process branches (subject, student identity, grade, preference, continue/end, feynman or transfer) present choices with `ask_user_question` so the Web card is clickable; teaching prompts that ask the student to think stay as plain text, never as options.
- Skills must be self-contained: no citation/provenance external URLs in `**/skills/**`; extract readable rules into the skill. Runtime material URLs are allowlisted only (`child-news-reader` today). See `docs/agents/skill-self-contained.md`.
- `node scripts/check-skills.mjs` is the static check for frontmatter, invocation policy, stale fields, dangling references, and non-allowlisted external URLs.
- `data/.../raw/` originals are read-only: never overwrite, edit, or delete one; a sent image may be archived there as a new original with its final name, and any rename backs up to `outputs/.../backups/raw/` first.
- `learn` stays subject-agnostic: start, initialization, target classification, recommendations, and teaching share `learn/skills/learn-data/references/teaching-resolver.md`. Real subject/task identity stays separate from teaching provider; applicable specialist packages use the resolved core/session names (usually `<subject>-core` / `<subject>-session`; mathematics uses unique band names), otherwise bundled `learn-general-core` / `learn-general-session` teach. The subject list lives only in `/learn-start`; stage/grade/preferences are optional. General evidence never auto-upgrades specialist mastery.
- Five learning-support needs are handled on demand by internal `learn-support`; one current teaching owner applies its advice. Support-only turns create no performance segment. Explicitly requested neutral plans/corrections use `support_events` and the same four-image finalize/marker-last replay; shared goals/preferences are changed only by start/profile. See `learn/skills/learn-data/references/session-schema.md` and `finalize-session.md`.
- `node --test scripts/skill-contracts.test.mjs` is the protocol regression check.
- Skill call graph, package deps, and usage-scenario Mermaid diagrams: `docs/skill-map/call-graph.md`.
