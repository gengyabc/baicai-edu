# Rule: Guidance Non-Response Handling

学生只给答案、简短回应、没有回应引导，或说“知道了”却未展示理解时，执行“先探查，后支架”。短答可能来自不熟悉环境、不爱说话、表达负担或知识困难；原因待查，不按字数或年级直接判为弱项。

## 1. 开放探查

沿用学生已经说出的内容，只补问一个开放问题，然后等待。例如学生回答 8+3 是“11”，回应：“你是怎么想到 11 的？”

- 首次探查保留学生自己的方法，不列出候选算法让学生选，也不先示范步骤。
- 学生已说出可检查的做法时，直接进入共享确认协议，无需重复探查。
- 空消息只表示没有收到内容；保留待答问题，不增加困难或确认失败次数。

完成条件：已发出一个开放邀请并等待，或已得到可检查的做法。尚未回答不算探查失败，不在同一回复追加支架。

## 2. 按回应分流

| 观察到的回应 | 下一动作 |
|---|---|
| 简短但能说明做法，或展示有效的图、算式、操作 | 按实际证据继续确认；表达长度不影响判断 |
| 仍短答、沉默，或表示不习惯、不想多说 | 降低表达负担，如“可以只写你先想到的那一步。”再等待；原因仍不明时保留未知 |
| “不知道怎么说” | 邀请写、画或展示已有过程，先区分表达困难与知识困难 |
| 明确说不会、请求帮助，或展示出具体错误、矛盾、卡点 | 围绕该卡点给最小支架 |
| 要求跳过、换题或结束 | 按 `references/session-end-signals.md` 处理意图；跳过请求本身不是能力证据 |

使用不同于教师预期但有效的方法，或只说“知道了”，均不足以认定不会。需要理解证据时，让学生展示一个实际步骤；依据步骤判断，而不是依据是否照教师指定的方法做。

完成条件：下一动作能对应学生实际回应；无法区分原因时保持未知，不补写心理原因或能力结论。

## 3. 最小支架与退让

确认卡点或学生主动求助后，每轮只提供一个刚好能帮助继续的提示，并留下由学生完成的部分。先澄清问题或缩小到卡住的一步；确有需要再给具体材料、局部示范或半完成步骤。年级只调整语言与材料，不作为困难证据。

- 每次提示后等待学生行动，再判断是否需要加一层；不一次列出多套方法或替学生完成推理。
- 连续开放探查与低负担邀请后仍无可用回应时，停止重复索要解释，按结束信号规则确认下一步；没有内容不等于不会。
- 支架尝试最多 3 次；仍卡住时交学科诊断，已有观察与未知项分开传递。
- 日志记录可观察事实，如“只回答 11，策略待确认”。困难、错误和阶段调整需要实际任务证据；教师提供的思路不算学生独立证据。

完成条件：学生已尝试下一步，或已进入明确的诊断/暂停分支；尚待回应时保持当前问题。

## 行为验收

- “11” → 只开放询问如何想到，不替学生列“接着数/重新数”等算法。
- “我不想打字” → 降低表达负担，不记录知识弱项。
- “8 后面数 9、10、11” → 已有策略证据，进入确认而非继续索要长解释。
- “我不会从 8 往后数” → 已有明确求助，给一个局部起点，剩下由学生尝试。
- 空消息或连续短答 → 保留未知；不会仅因此下调策略阶段。
