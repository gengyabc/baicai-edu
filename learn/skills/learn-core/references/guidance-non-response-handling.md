# Rule: Guidance Non-Response Handling

先按 `references/confirm-before-accept.md` 判断是否还需要证据；仅在确有缺口时执行本流程。短答可以是完整回答，原因不明时保留未知，不按字数或年级判为弱项。学科对照由各学科技能提供。

## 1. 开放探查

沿用学生已说出的内容，只补问一个开放问题后等待（如只给结论时问“你是怎么想到的？”）。

- 保留学生自己的方法；不列候选做法，不先示范。
- 已有可检查做法时直接进入确认，不重复探查。
- 空消息只表示未收到内容；保留待答问题，不增加困难或确认失败次数。尚未回答不算探查失败，不在同一回复追加支架。

## 2. 按回应分流

| 观察到的回应 | 下一动作 |
|---|---|
| 简短但能说明做法，或展示有效过程、证据、操作 | 按实际证据继续确认；表达长度不影响判断 |
| 仍短答、沉默，或不习惯、不想多说 | 降低表达负担后等待；原因不明时保留未知 |
| “不知道怎么说” | 邀请写、画或展示已有过程，先区分表达困难与知识困难 |
| 明确说不会、请求帮助，或出现具体错误、矛盾、卡点 | 围绕该卡点给最小支架（见下节） |
| 要求跳过、换题或结束 | 按 `references/session-end-signals.md` 处理；跳过本身不是能力证据 |

有效但非预期的方法、或只说“知道了”，不足以认定不会；需要证据时让学生展示一个实际步骤。异法与确认细节以 `references/confirm-before-accept.md` 为准。

## 3. 最小支架与退让

每轮只给一个刚好能继续的提示，留下由学生完成的部分；先缩小到卡住的一步，确有需要再给材料、局部示范或半完成步骤。年级只调语言与材料。

- 每次提示后等待，再决定是否加一层；不一次列多套方法或替学生完成推理。
- 追问预算以确认协议为准。降负担后仍无证据时，保留“策略待确认”，转近邻任务或按结束信号确认下一步；不要求先补完口头解释。
- 支架最多 3 次；仍卡住则交学科诊断，观察与未知分开传递。
- 日志写可观察事实（如“只给结论，策略待确认”）；困难、错误、阶段调整需任务证据，教学助手思路不算学生独立证据。
