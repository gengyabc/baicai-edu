# Rule: Session End Signals

`/learn`、`/feynman` 与学科技能按以下信号判断是否结束；写回由 `learn-data` 的 finalize 执行。

## Core Signals

### 1. 显式结束信号（立即结束）

当学生明确表达想结束时，视为立即结束信号，例如：

- "结束"
- "不学了"
- "不讲了"
- "我要走了"
- "今天到这"
- "今天就到这里"

### 1b. 歧义信号（先确认，不立即结束）

这些词常常表示“这一题做完了”，不是“今天的会话结束”：

- "好了"
- "可以了"
- "就这样"
- "行了"

先问一句：“你是想结束今天的练习，还是这题做完了想继续？”学生确认结束再 finalize；确认继续就回到教学。

### 1c. 危机信号（立即停止教学）

学生提到自伤、被伤害、被欺负、家里危险或不想活时，停止教学，按 `llm-safety-boundaries.md` 的危机流程处理，不进入 finalize，也不把细节写进学生档案。

### 2. 目标达成 / 讲解完成信号（建议结束）

#### learn 模式

当学生已完成当前学习目标的核心闭环时，可建议结束：

- 能清晰讲解当前目标内容
- 能应用所学解决当前类型问题
- 在 Feynman handoff 后能完整讲解

#### feynman 模式

当学生已完成当前讲解任务的核心闭环时，可建议结束：

- 能完整讲解目标内容
- 能回答 AI 对关键步骤或理由的追问
- 明确表示"讲完了"

### 3. AI 主动判断结束（建议结束）

当继续当前轮次已难以带来新的有效收获时，可主动建议结束：

- 当前学习目标已经足够覆盖
- 练习量已够，理解程度已达到本轮目标
- 学生已掌握本轮核心概念，再继续主要只会重复
- 当前讲解已经清晰完整，可自然收束本轮会话

### 4. 敷衍信号（谨慎触发）

当学生连续 2 次回复很短（少于 5 字）且与当前话题无关时，视为敷衍信号：

- 不立即强制结束
- 先提示："看起来你可能有点累了，要不要今天先到这？"
- 若学生顺势表达想结束，按显式结束处理

## Topic Switch Signal

当学生在当前会话中明确提出切换到新主题时，视为中断当前主题，例如：

- learn 模式："我想学 XXX"
- feynman 模式："我想讲 XXX"

这类情况应先结束当前主题，再开始新主题。

## Action Mapping

- 检测到显式结束信号：直接进入 finalize。
- 检测到目标达成 / 讲解完成 / AI 主动结束：先给学生一句阶段总结，再进入 finalize。
- 检测到中途换主题：先以 `status: "interrupted"` 保存当前 `session_segments`，再开启新主题。
- 检测到连续敷衍：先询问是否结束，不直接 finalize。
- 未结束：给一个明确的下一步（继续、变式练习、当小老师），等学生回应。

## Constraints

- 结束判断应服务于教学节奏，不应机械按轮数截断。
- 优先依据学生是否达成当前小目标，而不是追求更长对话。
- 不把短回答一律视为结束信号；低年级学生天然可能回答较短。

## Acceptance Criteria

此规则有效当：

- `/learn` 与 `/feynman` 不再各自维护大段重复的结束信号说明
- 所有入口共用同一套结束判断语义
- 入口 skill 负责 finalize，学科 skill 只负责判断与建议
